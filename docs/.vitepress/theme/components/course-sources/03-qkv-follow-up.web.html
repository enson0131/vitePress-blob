一、用一个例子理解 Q、K、V

假设输入一句话：

小明买了一台电脑，因为它运行速度很快。

模型需要理解「它」指的是谁。

我们把这个过程简化成：

  • Q（Query）：「它」正在寻找自己指代的对象。

  • K（Key）：「小明」「电脑」等 Token 提供可被匹配的特征。

  • V（Value）：被关注的 Token 提供信息，供「它」更新自身表示。

这里需要注意：Q、K、V 不是三段文字，也不是三个独立数据库，而是模型内部计算出来的数字向量。

二、Q、K、V 是如何计算出来的？

假设一个 Token 经过 Embedding 和前面网络层的处理，得到隐藏状态向量 XXX。

Transformer 会通过三个可学习的权重矩阵进行线性投影：

Q=XWQQ=XW_QQ=XWQ​
K=XWKK=XW_KK=XWK​
V=XWVV=XW_VV=XWV​

其中 WQW_QWQ​、WKW_KWK​、WVW_VWV​ 都是训练得到的参数。

也就是说，同一个 Token 的隐藏状态，可以被投影成三个不同用途的向量。

三、Q、K、V 如何一起工作？

核心公式：

Attention⁡(Q,K,V)=softmax⁡(QKTdk)V\operatorname{Attention}(Q,K,V) =\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)VAttention(Q,K,V)=softmax(dk​​QKT​)V

可以拆成三个步骤：

  1. Q × Kᵀ：计算 Query 和各个 Key 的匹配分数。

  2. Softmax：把分数转成注意力权重（实际还可能先应用 Causal Mask）。

  3. 权重 × V：对 Value 做加权求和，得到新的上下文表示。

五、为什么需要三个向量，而不是一个？

因为模型需要区分三个不同的任务：

  • 寻找信息：通过 Q 表达当前 Token 需要什么。

  • 匹配信息：通过 K 判断哪些 Token 值得关注。

  • 提取信息：通过 V 提供真正需要聚合的内容。

如果把 K 和 V 混成一个向量，匹配信息和传递信息就无法通过各自独立的投影进行学习，模型表达能力会受到限制。

另外，Multi-Head Attention（多头注意力）会使用多组 Q、K、V，让不同的注意力头学习不同的关系模式。

最后记住一句话：Q 负责提问，K 负责匹配，V 负责提供信息。

这三个向量共同决定了 Transformer 如何从上下文中提取和融合信息。
