四、长期记忆的数据结构

实际开发中，不建议只保存一段字符串。

可以使用以下 TypeScript 类型：

TypeScript
type MemoryRecord = {
  id: string;
  userId: string;

  scope: "user" | "project";

  content: string;

  category:
    | "preference"
    | "fact"
    | "task";

  sourceMessageId?: string;

  createdAt: string;
  updatedAt: string;
  expiresAt?: string;

  status:
    | "active"
    | "superseded"
    | "deleted";
};

为什么需要 status？

假设用户之前说：

代码示例优先 Python。

后来又说：

以后改成 TypeScript。

记忆系统不能让两条互相冲突的偏好同时生效。

更合理的方式是让新偏好生效，并将旧记录标记为已被替代。

五、Embedding 如何帮助检索记忆？

假设数据库保存了一条记忆：

用户喜欢使用 TypeScript 开发前端应用。

后来用户问：

我之前说过代码示例用什么语言吗？

这两句话并没有完全相同的关键词，但语义相关。

我们可以通过 Embedding 将文本转换成向量，再执行相似度检索。

典型流程：

纯文本
用户当前问题
     ↓
Embedding
     ↓
生成查询向量
     ↓
向量数据库检索
     ↓
获取相关记忆
     ↓
权限过滤与重排序
     ↓
注入当前上下文

不过，向量相似度高不代表信息一定正确。

实际系统还需要考虑记忆来源、时间有效性和用户权限。

六、TypeScript：实现一个简单记忆检索器

下面先用关键词匹配演示检索流程。

TypeScript
type Memory = {
  id: string;
  userId: string;
  projectId?: string;
  content: string;
  updatedAt: number;
  deleted?: boolean;
};

function retrieve(
  records: Memory[],
  userId: string,
  query: string,
  projectId?: string
) {
  const terms = query
    .toLowerCase()
    .split(/\s+/)
    .filter(Boolean);

  return records
    .filter(m =>
      m.userId === userId &&
      !m.deleted
    )
    .filter(m =>
      !m.projectId ||
      m.projectId === projectId
    )
    .map(m => ({
      record: m,
      score: terms.filter(t =>
        m.content.toLowerCase().includes(t)
      ).length
    }))
    .filter(x => x.score > 0)
    .sort((a, b) =>
      b.score - a.score ||
      b.record.updatedAt - a.record.updatedAt
    )
    .slice(0, 5)
    .map(x => x.record);
}

这是教学实现，并不具备真正的语义检索能力。

生产环境可以使用 PostgreSQL + pgvector 等方案。

注意：用户权限过滤应在可信数据库查询层完成，而不是先读取全部用户数据再交给模型判断。

七、长期记忆是否应该覆盖用户当前要求？

不应该。

例如，长期记忆中保存：

用户代码示例优先 TypeScript。

但用户这次明确要求：

请使用 Python 实现。

机器人就应该优先满足当前明确要求，而不是机械地坚持 TypeScript。

长期记忆应该作为辅助上下文，而不是不可修改的命令。

当然，用户当前要求也不能覆盖更高优先级的安全和权限约束。
