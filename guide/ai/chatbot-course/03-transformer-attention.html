Transformer 与 Attention：ChatGPT 为什么能理解上下文？

「吃苹果」和「苹果发布 iPhone」中的同一个词，为什么可以呈现不同语义？关键是 Transformer 的上下文计算。

一、为什么仅有 Embedding 还不够？

相同 Token ID 通常对应相同的初始 Token Embedding，但经过 Transformer 后，会形成上下文相关的隐藏状态。

苹果：相同初始 Embedding
↓ Self-Attention 与 Transformer
🍎 吃苹果：水果相关表示
📱 苹果发布 iPhone：公司相关表示

注意：GPT 采用因果掩码，句首「苹果」不能直接关注后面的 iPhone；后续位置可以结合前文。

二、Self-Attention 是什么？

Self-Attention 让当前位置根据 Query 与 Key 的匹配程度，对允许访问位置的 Value 进行加权聚合。

例如「小明把电脑放在桌子上，因为它太重了」，模型需要综合不同位置的信息来判断「它」的可能指代。

注意力权重不是模型决策的完整解释。

四、Attention 数学公式

Attention(Q,K,V) = softmax(QKᵀ / √dₖ) V

第一步计算 QKᵀ 匹配分数；第二步除以 √dₖ 缩放；第三步 Softmax 转为权重；第四步对 V 加权求和。

手算示例

假设已缩放分数为 [1,2,3]，Softmax 约为 [0.09,0.245,0.665]。

V1=[1,0], V2=[0,1], V3=[1,1]
0.09×V1 + 0.245×V2 + 0.665×V3
= [0.755, 0.910]

这是无因果约束的教学示例；GPT 类模型首位置不能看到未来 Token。

五、Multi-Head Attention

多个注意力头各自拥有投影参数，学习不同的关联模式。结果拼接后再经过线性投影。

↓
Head 1
Head 2
↓
Concat + 输出投影
MultiHead = Concat(head₁, …, headₕ) WO

六、为什么 ChatGPT 不能直接看到未来的 Token？

GPT 类模型通常使用 Causal Self-Attention（因果自注意力）。处理序列中的某个位置时，只能关注该位置及之前的位置，不能直接访问未来 Token。

我 → 喜欢 → JavaScript
处理「喜欢」时：可以参考「我」「喜欢」
不能直接参考后面的「JavaScript」

6.1 Causal Mask 如何实现？

注意力分数矩阵 S = QKᵀ / √dₖ。Softmax 之前加入掩码 M：当 j ≤ i 时 Mᵢⱼ = 0；当 j > i 时 Mᵢⱼ = −∞。

Attention Weights = softmax(S + M)

由于 exp(−∞) = 0，未来位置对应的注意力权重为 0。实现时可以采用大负数或专用掩码机制。

6.2 交互实验：因果注意力矩阵

交互实验：因果注意力矩阵

我喜欢学习人工智能我✓×××喜欢✓✓××学习✓✓✓×人工智能✓✓✓✓

当前选中「学习」：只允许关注自身及之前的位置。该矩阵展示可访问性，不是实际注意力权重。

6.3 为什么因果掩码重要？

如果训练时「喜欢」位置可以直接看到需要预测的「JavaScript」，模型就可能偷看答案。因果掩码保证训练目标符合逐 Token 生成的约束。

注意：模型可以看到用户已经发送的完整问题，但不能提前看到自己尚未生成的回答。

七、Transformer Block 除了 Attention 还有什么？

典型现代 GPT 类 Transformer Block 还包括前馈网络（FFN）、残差连接、归一化等机制。不同架构的顺序可能不同。

Transformer Block（Pre-Norm 概念示意）
输入隐藏状态 X
↓
Normalization
↓
Causal Self-Attention
↓
Residual Add（加上原始输入）
↓
Normalization + FFN
↓
Residual Add → 输出隐藏状态

7.1 Feed Forward Network

Attention 主要负责聚合上下文信息，FFN 对每个位置的隐藏状态执行非线性变换。

FFN(x) = W₂ σ(W₁x + b₁) + b₂

这是经典 FFN 的简化公式。实际现代模型可能使用门控 FFN 等变体。

7.2 Residual Connection

y = x + F(x)

残差连接让原始信息有直接传播路径，有助于深层网络的梯度传播与训练。

7.3 Normalization

LayerNorm 或 RMSNorm 等归一化操作有助于改善数值尺度和训练稳定性，具体位置随架构变化。

八、TypeScript 工程实践：Attention 与聊天历史有什么关系？

Self-Attention 是模型内部机制；聊天历史管理是应用层职责。模型无法利用未传入的历史消息。

假设用户先说「我正在学习 React」，再问「它和 Vue 有什么区别？」。如果只发送第二句话，模型就可能缺少「它」指 React 的背景。

8.2 为什么上下文窗口有限？

模型有上下文长度限制。输入、系统提示词与输出需要符合相应预算；历史越来越长时，应用应裁剪较早消息、摘要或检索相关记忆。

上下文管理流程
完整聊天历史
↓
估算 Token 使用量
↓
保留关键历史，摘要较早消息
↓
组装 Messages 并调用 LLM

8.3 Attention 的计算成本

标准全量 Self-Attention 的分数矩阵大小为 n × n，相关计算规模通常随序列长度呈二次增长 O(n²)。实际推理性能还受 KV Cache、FlashAttention、模型结构等影响。

学习疑问与解答

Q1：Self-Attention 是否根据上下文动态赋予每个 Token 语义？

提问日期：2026-10-15

更准确地说，Self-Attention 动态聚合上下文信息并更新 Token 的向量表示，而不是直接分配语义标签。

同一个 Token 的初始 Embedding 可以相同，但多层 Transformer 计算后隐藏状态不同。GPT 的因果掩码还限制了当前位置能够访问的上下文。

复习要点：动态更新的是表示，不是直接给 Token 打标签。

Q2：Q、K、V 分别代表什么？为什么要分成三个向量？

Q、K、V 是 Transformer 中 Self-Attention（自注意力机制） 的三个核心概念。

一、用一个例子理解 Q、K、V

假设输入一句话：

小明买了一台电脑，因为它运行速度很快。

模型需要理解「它」指的是谁。

我们把这个过程简化成：

  • Q（Query）：「它」正在寻找自己指代的对象。

  • K（Key）：「小明」「电脑」等 Token 提供可被匹配的特征。

  • V（Value）：被关注的 Token 提供信息，供「它」更新自身表示。

这里需要注意：Q、K、V 不是三段文字，也不是三个独立数据库，而是模型内部计算出来的数字向量。

二、Q、K、V 是如何计算出来的？

假设一个 Token 经过 Embedding 和前面网络层的处理，得到隐藏状态向量 XXX。

Transformer 会通过三个可学习的权重矩阵进行线性投影：

Q=XWQQ=XW_QQ=XWQ​
K=XWKK=XW_KK=XWK​
V=XWVV=XW_VV=XWV​

其中 WQW_QWQ​、WKW_KWK​、WVW_VWV​ 都是训练得到的参数。

也就是说，同一个 Token 的隐藏状态，可以被投影成三个不同用途的向量。

三、Q、K、V 如何一起工作？

核心公式：

Attention⁡(Q,K,V)=softmax⁡(QKTdk)V\operatorname{Attention}(Q,K,V) =\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)VAttention(Q,K,V)=softmax(dk​​QKT​)V

可以拆成三个步骤：

  1. Q × Kᵀ：计算 Query 和各个 Key 的匹配分数。

  2. Softmax：把分数转成注意力权重（实际还可能先应用 Causal Mask）。

  3. 权重 × V：对 Value 做加权求和，得到新的上下文表示。

五、为什么需要三个向量，而不是一个？

因为模型需要区分三个不同的任务：

  • 寻找信息：通过 Q 表达当前 Token 需要什么。

  • 匹配信息：通过 K 判断哪些 Token 值得关注。

  • 提取信息：通过 V 提供真正需要聚合的内容。

如果把 K 和 V 混成一个向量，匹配信息和传递信息就无法通过各自独立的投影进行学习，模型表达能力会受到限制。

另外，Multi-Head Attention（多头注意力）会使用多组 Q、K、V，让不同的注意力头学习不同的关系模式。

最后记住一句话：Q 负责提问，K 负责匹配，V 负责提供信息。

这三个向量共同决定了 Transformer 如何从上下文中提取和融合信息。
